# Branch work notes

The user wants short notes on every branch they work in so they can remember the latest work.

- Read `notes/branches/<branch>.md` at the start of related work. Get the actual branch name from Git; replace `/` with `--` in the filename.
- Before finishing work, create or update that branch's note with the date, latest completed changes, relevant verification, and remaining next steps. Keep it short; replace stale status instead of accumulating a long log.
- Notes must distinguish completed work from proposed work and live changes from local changes.
- Stay on the user's working branch. Do not switch branches just to create notes elsewhere.
